# Skill: измеримый NFR

## Когда использовать

В `NFR-*` стоит оценка без числа: «быстро», «надёжно», «удобно»,
«масштабируемо». Применяется на стадии System analysis до SA-gate, вместе с
`skills/analyze-data/SKILL.md` (база и формула).

## Что делать

1. **Возьми один `NFR-*`.** Одно требование — один показатель. Два показателя
   в одной строке раздели.
2. **Назови метрику.** Latency p95, throughput (RPS), uptime %, error rate,
   RTO/RPO, contrast ratio, TTFB. Метрика без имени не проверяется.
3. **Задай порог и условие.** «p95 ≤ 300 мс при 100 RPS в регионе РФ» —
   порог, нагрузка и контур. Порог без условия — пожелание.
4. **Назови метод проверки.** Нагрузочный тест, мониторинг за период, аудит,
   автоматическая проверка WCAG. Метод — то, чем порог будет измерен.
5. **Если порог обосновать нельзя — фиксируй пробел.** Пиши
   `[не измеримо: нет базы / нет данных]` и открытый вопрос. Не выдумывай
   число, чтобы закрыть строку.
6. **Заполни колонки** «Мера / Порог» и «Метод проверки» в
   `nonfunctional-requirements.md`; при отсутствии колонок — добавь их из
   `templates/nonfunctional-requirements.md`.

## Чего нельзя

- Оставлять «быстро» и «удобно» как требование.
- Ставить порог без базы сравнения или без условия измерения.
- Смешивать единицы и периоды в одном пороге.
- Выдавать целевую цифру за измеренную.

## Метрики / проверка

- У каждого `NFR-*` есть мера + порог + метод, либо маркер `[не измеримо]`.
- Порог пересчитывается/проверяется методом из строки.
- `check_run.py` проверяет заполненность колонок, когда они есть в шапке.
