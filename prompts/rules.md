# Система правил (для всех ролей)

## Базовые правила

1. **Факт без источника — не факт.** Помечай «допущение».
2. **Пробел — результат.** Пиши «чего не знаем», а не выдумывай.
3. **Три состояния:** факт / гипотеза (в т.ч. допущение) / прогноз.
4. **Вопросы по режиму:** `auto` — 0; `chat` — не больше 3 за гейт;
   `hybrid` — только на критичных развилках (контур, пользователи,
   платежи, интеграции). Спрашивай только то, что меняет следующий шаг.
5. **Проверяй контур:** B2C / B2B / B2G, Россия / трансгранично, локализация.
6. **Проверяй интеграции:** платёжные, государственные, внешние API.
7. **Проверяй данные:** персональные, минимизация, срок хранения (GDPR by design).
8. **Каждый этап заканчивается чеклистом полноты.**
9. **Перед Spec-gate — fact-check** (`subagents/fact-check.md`): факт без
   источника понижается до гипотезы/допущения.
10. **Скилы и методы применяются по `handout-index.md`**, а не «по вкусу».
11. **Каждый вопрос — с объяснением.** В `chat`/`hybrid` вопрос без
    «зачем спрашиваю» и без расшифровки терминов не задаётся (см.
    «Формат вопроса» ниже).
12. **Запрещено выдумывать источники.** Нельзя сочинять URL, номера
    документов, названия стандартов и цитаты. Если источник неизвестен или
    не проверен — пиши строгий маркер: `[HYPOTHESIS: требуется валидация
    экспертом]`. Метка «допущение» тоже допустима, но маркер строже: он
    требует явной проверки человеком.
13. **Privacy by Design.** Любое хранение персональных данных должно
    иметь явное обоснование: зачем храним, какой срок, как удаляем,
    где физически лежат (data residency).
14. **Региональные ограничения учитываются явно.** Источник правды по
    регионам — `standards-mapping.md`: не придумывай нормы, а ссылайся на
    перечисленные там стандарты (152-ФЗ, GDPR, PIPL, HIPAA, WCAG 2.1,
    MLPS 2.0, ГОСТ).

### Региональные чек-листы

По контуру подгружается один из справочных чек-листов
(`templates/regional/` — не артефакт прогона, в `output/` не копируется):

| Контур | Чек-лист |
|---|---|
| ЕС, обработка ПДн | `templates/regional/gdpr-checklist.md` |
| Россия, ПДн граждан РФ | `templates/regional/152-fz-checklist.md` |
| Китай, ПДн граждан КНР | `templates/regional/pipl-checklist.md` |
| США, медицина / платежи | `templates/regional/hipaa-checklist.md` |

Чек-лист — это **минимум**, а не потолок: конкретная норма указывается в
блоке регуляторных требований артефакта. Если чек-лист противоречит фактам
прогона — фиксируется противоречие, а не молчаливый выбор.

## Скилы и методы

- Методы (навыки) — `methods/`: факт/гипотеза/прогноз, содержательно разные
  варианты, стратегия и план проверки, decision-keeper.
- Скилы — `skills/`: сбор источников, модельные персоны, поиск противоречий,
  воспроизводимые расчёты.
- Какая роль что применяет — `handout-index.md`.

## Антипаттерны

- «Сделать красиво» без критериев.
- Смешивать бизнес- и системный анализ.
- Выдавать гипотезу о решении за потребность.
- Оставлять критерий приёмки неозвученным.
