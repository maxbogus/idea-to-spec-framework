# Чеклисты гейтов — справочник оркестратора и вход отдельного вызова гейта

> Генерируется `scripts/render_gate_checklists.py` из
> `prompts/gate-checklists.yaml`. Не править вручную: проверка —
> `make check-gates`, перегенерация — `make gates-index`.
>
> В промпт оркестратора и ролей файл **не подключается**: измерено
> (qwen2.5:7b), что чеклист внутри промпта модель принимает за формат
> ответа и отвечает чеклистом вместо JSON роли.
>
> Отдельному вызову гейта (`prompts/roles/gate-reviewer.md`) чеклист
> передаётся во входе — там он и есть предмет проверки. Вердикт
> возвращается как `checks[]` со статусом по каждому id.

## Чеклист BA-gate

Этап: `ba_gate`. Возврат доработки: `business`.
Владельцы: `business-analyst`, `product-manager`.

- [ ] `BA-01`. problem statement сформулирован
- [ ] `BA-02`. success metric измерим
- [ ] `BA-03`. персоны и контур определены
- [ ] `BA-04`. JTBD (работы) сформулированы и связаны с персонами
- [ ] `BA-05`. JTBD связаны с success metric (через Product Manager)
- [ ] `BA-06`. scope разделён: MVP (must-have) и полный scope (MoSCoW)
- [ ] `BA-07`. домены и тарифы названы — допустим статус `na` с причиной
- [ ] `BA-08`. ограничения зафиксированы
- [ ] `BA-09`. открытые вопросы выписаны

## Чеклист SA-gate

Этап: `sa_gate`. Возврат доработки: `system`.
Владельцы: `system-analyst`.

- [ ] `SA-01`. use cases описаны
- [ ] `SA-02`. функциональные требования перечислены
- [ ] `SA-03`. нефункциональные требования перечислены
- [ ] `SA-04`. интеграции названы
- [ ] `SA-05`. данные и безопасность учтены
- [ ] `SA-06`. acceptance criteria в формате BDD (Given/When/Then)
- [ ] `SA-07`. для risk high проведён STRIDE threat modeling — допустим статус `na` с причиной
- [ ] `SA-08`. NFR включает accessibility (WCAG 2.1 AA минимум)
- [ ] `SA-09`. у каждого NFR есть мера, порог и метод проверки (или маркер «не измеримо»)
- [ ] `SA-10`. у каждого FR есть негативный критерий приёмки (BDD)
- [ ] `SA-11`. блок регуляторных требований заполнен — допустим статус `na` с причиной

### Чек-лист безопасности (для high-risk доменов)

- [ ] `SA-12`. OWASP Top 10 проверен — допустим статус `na` с причиной
- [ ] `SA-13`. STRIDE threat model построен — допустим статус `na` с причиной
- [ ] `SA-14`. классификация данных выполнена (public / internal / confidential / restricted) — допустим статус `na` с причиной
- [ ] `SA-15`. шифрование при хранении и передаче подтверждено — допустим статус `na` с причиной

## Чеклист Spec-gate

Этап: `spec_gate`. Возврат доработки: `architecture`, `system`.
Владельцы: `system-analyst`, `architect`.

- [ ] `SP-01`. спецификация полна
- [ ] `SP-02`. traceability matrix намечена: связь BR → FR заполнена; задачи T-* и статусы покрытия добавляет Plan
- [ ] `SP-03`. risk register заполнен
- [ ] `SP-04`. human oversight plan намечен
- [ ] `SP-05`. fact-check прогнан, hallucination-log.md заполнен
- [ ] `SP-06`. requirements-critic прогнан, расхождения зафиксированы и не сглажены
- [ ] `SP-07`. все допущения помечены как гипотезы
- [ ] `SP-08`. требования с risk high имеют threat model — допустим статус `na` с причиной
- [ ] `SP-09`. ADR имеют статус, минимум две альтернативы и последствия
- [ ] `SP-10`. региональные ограничения отражены (152-ФЗ / GDPR / PIPL / HIPAA)
