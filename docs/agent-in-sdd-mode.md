# Агент в режиме SDD: механики, guardrails, структура spec-файлов

> **Назначение.** Закрывает пункт 3 отзыва: «как именно заставить агента
> работать в режиме SDD». Наш репозиторий здесь — разобранный пример, а не
> реклама: показано, что работает, чем проверяется и **чего у нас нет**.
>
> **Дата:** 2026-11-25. Связанные документы: `prompts/start.md`,
> `prompts/orchestrator.md`, `scripts/check_run.py`, `docs/prompt-anatomy.md`.

## 0. Почему «просто попросить» не работает

Модель не «знает фаз» — она оптимизирует локальный ответ. Просьба «работай
по SDD» без структуры даёт три типовых сбоя:

1. **Пропуск фазы.** Сразу пишется `spec.md`, минуя бизнес-анализ и гейт.
2. **Подмена схемы.** Перечисление артефактов в промпте модель принимает за
   имена полей ответа (измерено: `f89afa0` / инцидент ORCH).
3. **Потеря хвоста формата.** Чем длиннее ответ, тем вероятнее выпадут
   последние поля (F021: граница 8B-модели ~3.2–3.5 КБ ответа).

Лечение — не «более строгая просьба», а четыре механики ниже.

## 1. Четыре механики

### 1.1 System-prompt: роль, формат, границы

Промпт роли задаёт три вещи и **ничего лишнего**:

- **роль и границы:** что делает и чего не делает («не смешивай бизнес- и
  системный анализ»);
- **формат ответа:** один JSON-объект с перечисленными полями; поля
  обязательны, «нет данных» — содержательное допущение, а не пустой список;
- **запреты:** не выдумывать источники, не переопределять режим, не
  констатировать провал гейта без адресата возврата.

Два измеренных правила размещения (подробно — `docs/prompt-anatomy.md`):

- **режим — рядом со входом**, а не в начале промпта (F020);
- **разъяснение формата — перед JSON-блоком**, не после (F022).

### 1.2 Структура spec-файлов: ID как контракт

У нас артефакты связаны идентификаторами, а не пересказом:

```
brief.md → business-requirements.md (BR-*)
         → personas.md (P-*), jtbd.md (J-*)
         → use-cases.md (UC-*) → functional-requirements.md (FR-*, AC-*)
         → nonfunctional-requirements.md (NFR-*)
         → spec.md §1…§9 → traceability-matrix.md → diagrams/*.mmd
```

Правила, без которых структура рассыпается:

- **каждый ID существует один раз** и упоминается, а не переизобретается;
- **диаграмма — производная:** узлы берутся из `UC-*`, `J-*`, `BR-*`,
  новых сущностей не придумывается;
- **memory bank ≠ спека:** `AGENTS.md` отвечает «как мы работаем в
  репозитории», `spec.md` — «что делает эта фича». Смешение распухает спеку.

### 1.3 Guardrails: детерминированные проверки

Спека сужает пространство решений, но не гарантирует поведение (канон §5.3).
Поэтому у нас проверяет **код**, а не модель:

| Проверка | Что ловит |
|---|---|
| `scripts/check_run.py` | FR→BR, J→P, UC→J, lifecycle требования, AC, покрытие traceability, `Q-*` → ответ, узлы диаграмм, раздел «Гейты» (`checks[]`) |
| `scripts/check_dor.py` | применимость диаграмм (`not_applicable` с причиной), полнота по профилю, шаблонные пустышки |
| `scripts/check_gate.py` | вердикт гейта: полнота `checks` по чеклисту, `na` только для условных пунктов, согласованность `status`/`missing`/`return_to` |
| `scripts/check_cross_refs.py` | идентификаторы в схемах ролей согласованы между собой |
| `scripts/check_artifact_policy.py` | PII/секреты в артефактах → human-review (гейт не роняет) |
| `scripts/check_ledger.py` | формат измерений и решений (`prompts/ledger/*.jsonl`) |
| `scripts/check_skills_registry.py` | скил без записи, semver, зависимости, evals |
| `scripts/check_slides_overflow.py` | переполнение слайдов (headless Chrome) |
| `eval/` (promptfoo, pytest) | контракты ответов ролей; провал = `xfail(strict)`, а не маскировка |

Всё это собирается в `make check` и `make test-eval`.

**Честно:** agent hooks (события «перед коммитом», «после записи файла») у
нас **не используются**. Ближайший аналог — `make check` в pre-push/CI.
Это осознанно: hook, который молча не сработал, хуже отсутствующего hook.

### 1.4 Фазы и гейты: что дальше и когда стоп

```
Intake → Business (PM+BA) → BA-gate → Design (Sketch) → System (SA) → SA-gate
       → Architecture → fact-check → Spec-gate → Plan → Design (CJM) → отчёт
```

- **Гейт — это критерий + владелец + артефакт.** Провал возвращает на
  доработку со списком недостающих пунктов, а не констатирует неполноту.
- **Режим диалога:** `auto` — без вопросов; `chat` — ≤3 вопросов за гейт;
  `hybrid` — только на развилках (контур, пользователи, платежи, интеграции).
- **Критерий остановки:** ответ перестал менять следующий шаг или снижать
  риск — спрашивать прекращаем, фиксируем допущение.
- **Чеклисты — справочник**, а не формат ответа: иначе модель начинает
  «заполнять чеклист» вместо ответа своей роли.

## 2. Пайплайн как разобранный пример

| Шаг | Артефакт | Гейт | Чем проверяется |
|---|---|---|---|

## 3. Как перенести это на свой проект

Минимальный работающий набор — три файла и один скрипт:

1. `AGENTS.md` — правила репозитория (роли, границы, команды).
2. `spec.md` — один артефакт с критериями приёмки в GIVEN/WHEN/THEN.
3. `check_spec.py` — проверка: у каждого требования есть AC и ссылка на цель.
4. `make check` — запуск проверки; провал останавливает работу.

Расширение до полного контура — по шагам:

| Шаг | Что добавить | Зачем |
|---|---|---|
| 1 | формат ответа роли (JSON, обязательные поля) | иначе хвост формата теряется |
| 2 | ID-контракт (`BR-*`, `FR-*`, `AC-*`) | трассируемость без пересказа |
| 3 | детерминированный чекер | отделяет SDD от «промпта в файле» |
| 4 | гейты с адресатом возврата | провал становится задачей, а не констатацией |
| 5 | eval-контракты на роли | регрессия промпта видна до участника |
| 6 | ledger измерений | решения опираются на замеры, а не на память |

## 4. Чего у нас нет (границы примера)

- **Hooks.** Автоматического запуска на события нет; проверка — явная
  команда `make check` (в CI/pre-push).
- **Генерации кода из спеки.** Мы не spec-as-source: код по спеке пишет
  человек или другой агент, а спека проверяется гейтами (см.
  `docs/sdd-landscape.md` §4).
- **Внешнего рантайма.** Оркестрация — промпт-харнесс в чате, не LangGraph
  и не CrewAI (почему — `docs/tool-comparison.md`).
- **IDE-интеграции.** Нет хуков и панелей вроде Kiro; всё живёт в файлах и
  командах.

## 5. Антипаттерны

| Антипаттерн | Симптом | Лечение |
|---|---|---|
| Промпт-простыня | «добавим ещё абзац, и модель поймёт» | сокращать, а не добавлять (F019: +1.9 КБ → 4/6→2/6) |
| Схема из перечисления | модель подставляет артефакты вместо полей | список этапов без перечисления артефактов |
| Разъяснение после JSON | правило игнорируется | перенести разъяснение перед блоком (F022) |
| Чеклист в промпте | модель «заполняет чеклист» вместо ответа | чеклисты — отдельный справочник |
| Спека без гейта | документ есть, поведение не проверяется | минимум одна машинная проверка на AC |
| Надежда на «модель поймёт» | провал воспроизводится, причина неизвестна | ledger: замерить, записать, проверить A/B |
