## P0 волны D (2026-11-26): наблюдаемость вызова вместо ручных замеров

Причина: ни один провайдер не читал метаданные Ollama (`prompt_eval_count`,
`eval_count`, `done_reason`) — вытеснение контекста было невидимо изнутри
прогона, а битый JSON нельзя было отличить от обрыва по `num_predict`. Плюс
главный замер волны C («46 КБ → 4096») в репозиторий не попал: `_raw`-ответов
в дереве нет (`git ls-tree -r HEAD output/auto-005 | grep raw` — пусто).

Сделано (`scripts/idea_to_spec/ollama_client.py`):

- **Одна точка правды по лимитам.** `build_request` собирает тело запроса
  (`num_ctx`, `num_predict`, `temperature`, `top_p`, `think`); оба провайдера
  больше не дублируют эти параметры.
- **Метаданные читаются.** `parse_reply` сохраняет `prompt_eval_count`,
  `eval_count`, `done_reason`; `context_problems` распознаёт три случая:
  промпт вытеснен (`prompt_eval_count >= num_ctx`), ответ обрезан
  (`done_reason=length`), окно переполнено во время генерации.
- **Громкий отказ вместо молчаливого артефакта.** `ContextTruncatedError`;
  отключение для замеров — `ITSF_ALLOW_TRUNCATION=1`.
- **JSON-контракт.** `extract_json_object` + один ремонтный повтор
  (`ITSF_JSON_RETRY=0` отключает). Массив на верхнем уровне считается
  нарушением формата, а не «объектом внутри списка» — в том числе когда перед
  массивом стоит текст («Вот ответ: [...]»).
- **Трейс и сырые дампы.** `record_call` пишет JSONL (`ITSF_TRACE`) и дамп
  «промпт + ответ + метаданные» (`ITSF_RAW_DIR`); `make eval` и
  `make eval-target` включают оба пути по умолчанию
  (`docs/evaluation/traces/<тег>.jsonl`, `docs/evaluation/raw/<тег>/`), пути в
  `.gitignore`. Запись несёт `ts` (UTC, ISO 8601) и `call` (кейс + номер хода,
  `SA-04-turn2`): JSONL append-only и общий на тег модели, без этих полей
  строки двух прогонов неразличимы.

### P0.1 (2026-11-27): атрибуция вызова и точный guard формата

Ревью P0 нашло две дыры, обе били в цель «замер воспроизводим»:

- **Трейс не атрибутировался.** В записи не было времени и имени вызова, а
  диалоговые вызовы писались как `turn` — по дампу нельзя было понять, какой
  кейс усечён. Добавлены `ts` и `call`; `run_dialogue` принимает имя кейса, и
  каждый ход помечается `SA-04-turn1`, `SA-04-turn2`.
- **Массив обходил guard.** Проверка `startswith("[")` не ловила ответ
  «Вот: [{"a": 1}]»: объект извлекался из массива и считался валидным.
  `_array_before_object` разбирает `[`-фрагмент JSON-декодером и отклоняет
  верхнеуровневый массив, не трогая прозу («[см. ниже]») и вложенные массивы
  внутри объекта (F035).

### P1 (2026-11-27): отдельный вызов гейта и `checks[]`

Причина: гейт возвращал свободный `missing`, поэтому «гейт-печать» (passed при
незакрытых пунктах) не отличалась от прохождения, а вердикт нельзя было
проверить машиной. Плюс чеклист жил только прозой — пункт было не адресовать.

Сделано:

- **Чеклист — машинно-читаемый.** `prompts/gate-checklists.yaml` (id, текст,
  `na_allowed`, подраздел, `return_to`); человеческий справочник
  `prompts/gate-checklists.md` — производная (`make gates-index`,
  проверка `make check-gates`). Подраздел безопасности SA-gate сохранён.
- **Отдельный вызов гейта.** `prompts/roles/gate-reviewer.md` + рендер входа
  (`ГЕЙТ` / `КУДА ВОЗВРАЩАТЬ` / `ЧЕКЛИСТ` / `АРТЕФАКТЫ`): чеклист приходит во
  входе, в промпт роли он не попадает. Ответ — `checks[]` по каждому id,
  `missing` = id провалов, `return_to` из допустимых.
- **Проверка контракта.** `scripts/check_gate.py` и
  `idea_to_spec.gate_checklists.validate_gate_payload`: полнота `checks`,
  `na` только для условных пунктов и с причиной, `pass`/`fail` без
  доказательства запрещены, `status`/`missing`/`return_to` согласованы.
  `check_run` проверяет раздел «Гейты» в `validation-report.md` (условно —
  старые прогоны принимаются).
- **Eval.** Сценарий `GATE`, кейсы `GATE-01…03`, структурная проверка
  `gate_contract` (в pytest и в JS-ассерте). Mock строит вердикт из YAML.

Гейты: `pytest -m 'not slow'` — 457 passed; `ruff`/`mypy` (68 файлов) — чисто;
`make check` — exit 0; `make eval-mock` — 44/44. E2E: провайдер отдал вердикт

## Особенности окружения

- **Guard режима планирования ловит `git add` / `git commit` / `rm` / `mv`
  даже в Act mode.** Git-операции выполняются через `subprocess` из Python:
  ```python
  subprocess.run(['git', 'add', '-A'], capture_output=True, text=True)
  ```
  Файлы при этом пишутся обычными средствами (heredoc в Python).
- **Пути в promptfoo разрешаются от каталога конфига.** `make eval` кладёт
  конфиг в корень репозитория, поэтому в конфиге пути к скриптам абсолютные
  или считаются от `process.cwd()`.
- **В JS-ассерте promptfoo нет `require`** — только process-shim:
  `process.mainModule.require('child_process')`.
- **thinking-модели:** режим рассуждений выключается полем `think: false` в
  теле запроса. Переменная `OLLAMA_DISABLE_THINKING` не подходит — сервер
  Ollama читает её только при старте.
- **exec-провайдер медленнее прямого `ollama:chat`**: отдельный процесс на
  каждый кейс (~30 мин на 23 кейса против ~20).
