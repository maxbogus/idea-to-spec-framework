# Use cases

| ID | Актор | Цель | Предусловие | Шаги | Постусловие |
|---|---|---|---|---|---|
| UC-1 | P-1 / P-4 | Извлечь атрибуты из одной карточки (J-1, J-4) | есть title + description | 1. Отправить карточку в POST /api/v1/extract. 2. Stage 0: HTML-strip, truncate, leakage-filter. 3. Rules v2 + catalog model извлекают атрибуты. 4. Verifier проверяет source_span / value_set / unit. 5. Вернуть JSON (value, confidence, source_span, status) | карточка размечена; спорные значения — в review |
| UC-2 | P-1 | Обработать партию карточек CSV/XLSX (J-1) | есть файл партии | 1. Загрузить файл. 2. Создать job. 3. Потоковая обработка карточек. 4. Отдавать статус и прогресс. 5. Экспорт результатов | партия обработана, job закрыт, результаты выгружены |
| UC-3 | P-1 | Проверить очередь сомнительных значений (J-1) | есть low-confidence очередь | 1. Открыть список «на проверку». 2. Увидеть подсветку цитаты (source_span). 3. Принять или исправить значение. 4. Подтверждение → значение идёт в карточку | очередь сокращена; правки человека — разметка |
| UC-4 | P-2 | Добавить новую категорию и увидеть метрики (J-2) | есть конфиг схемы категории | 1. Загрузить схему атрибутов. 2. Прогнать на gold категории. 3. Получить F1 / precision по атрибутам. 4. Сравнить с baseline | категория подключена, метрики видны |
| UC-5 | P-3 | Найти товар по фильтру (J-3) | товар с заполненным атрибутом | 1. Выбрать фильтр (напр. «256 ГБ»). 2. Система фильтрует по атрибуту. 3. Показать все подходящие предложения | покупатель видит полный набор |

## Правила

- Актор — из `personas.md`, а не придуманный.
- Каждый `UC-*` трассируется до `J-*` из `jtbd.md`.
- `UC-5` — транзитивный сценарий (P-3 выгодоприобретатель); он закрывается
  качеством каталога, а не отдельным экраном сервиса.
- Шаги — проверяемые, без «сделать красиво».
