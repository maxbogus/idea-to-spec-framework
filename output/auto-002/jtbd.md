# JTBD — Jobs To Be Done

> Работа, которую персона «нанимает» продукт выполнить. Отвечает на вопрос
> «зачем пользователю продукт» — до того, как появляются use cases.
> Строится из `personas.md`. Персоны: **P-1 … P-4**.

## Job stories

Формат: «Когда <ситуация>, я хочу <мотивация>, чтобы <ожидаемый результат>».

| ID | Персона | Когда (ситуация) | Хочу (мотивация) | Чтобы (результат) | Тип |
|---|---|---|---|---|---|
| J-1 | P-1 | приходит партия карточек от партнёра | проверять только сомнительные значения | каталог рос без роста ручной работы | функц. |
| J-2 | P-2 | появляется новая категория | добавить её атрибуты по конфигу и сразу увидеть метрики | не дообучать модель с нуля и не платить за LLM на каждую карточку | функц. |
| J-3 | P-3 | ставлю фильтр «256 ГБ» | видеть все подходящие предложения | сравнивать и выбирать без пропусков | функц. |
| J-4 | P-4 | загружаю товар в своём формате | чтобы товар сразу попадал в фильтры | продаваться без переписывания карточки | функц./эмоц. |

## Связь с требованиями

- Каждый `UC-*` в `use-cases.md` трассируется до `J-*`.
- JTBD — это работа, а не решение: «хочу проверять только сомнительное»
  (работа), а не «хочу кнопку approve» (решение).

## Чего не знаем

- Реальных интервью не было — сказано явно.
- Источник каждого job story: бриф М.Видео / гипотеза.
- P-3 / P-4 — выгодоприобретатели: их JTBD закрывается транзитивно, через
  качество каталога, а не напрямую нашим UI (**[допущение]**).
