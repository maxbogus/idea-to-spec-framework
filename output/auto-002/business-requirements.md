# Бизнес-требования

## Персоны

| Персона | Роль | Контекст |
|---|---|---|
| P-1 | Специалист по качеству каталога | принимает партии карточек |
| P-2 | ML-инженер каталога | добавляет категории, смотрит метрики |
| P-3 | Покупатель | ищет по фильтрам |
| P-4 | Партнёр-продавец | загружает карточки |

## Контур

B2B, Россия, RU/EN, внутренний инструмент М.Видео. Монетизация — **[допущение]**.

## AS-IS

- Характеристики спрятаны в свободном тексте; в структурированных полях их
  нет. **[факт]** (`CASE.md §2`).
- 48.9% описаний содержат HTML-мусор; 60% кликов без brand в полях.
  **[факт]** (`01-product-context.md`).
- Заполнение ручное; при росте каталога (200k → 450k → 1M) ручной труд не
  успевает. **[факт]** (`01-product-context.md §1`).

## TO-BE

- Пайплайн извлекает обязательные атрибуты, нормализует и отдаёт confidence
  + цитату. **[факт]** (`03-pipeline.md`).
- Человек проверяет только очередь сомнительных значений. **[факт]**
  (`04-value-economics.md §1`).

## Варианты решения

- **Оставить как есть** — ручное заполнение каталога.
  Возражения: ручной труд не масштабируется на 1M+ карточек; каждая новая
  категория = новая ручная работа; доля незаполненных brand не падает.
- **Закрыть направление** — не делать автозаполнение, оставить только отчёт
  о качестве.
  Возражения: не решает боль «товар не попадает в фильтр»; конкуренты
  (Ozon/Я.Маркет/Walmart) уже автоматизируют — отставание по GMV.
- **Основной** — гибридный пайплайн (rules → catalog model → LLM opt-in →
  verifier) с честной уверенностью и цитатой.
  Возражения: нужен gold-набор (его нет из коробки); риск галлюцинаций LLM;
  экономика держится на том, что большинство карточек закрывается без LLM.

## Критерии приёмки

| ID | Критерий | Как проверить |
|---|---|---|
| AC-1 | F1 ≥ 80% на слепом test (baseline 10.6%) | `make eval-real`, замороженный test |
| AC-2 | Доля выдуманных значений ≈ 0 (source_span ⊂ text) | verifier + метрика «доля выдуманного» |
| AC-3 | 100% валидный JSON на прогоне | JSON Schema контракт тестов |
| AC-4 | Precision «в карточку» ≥ 90% при пороге 0,85 | `make eval-real` (P 96.5% @ accept 66.8%) |
| AC-5 | Цена 1000 карточек дешевле чистой LLM; latency p95 в бюджете | `make economics`, latency-замер |
| AC-6 | Нормализация вариантов значения даёт одно каноническое значение | unit-тесты normalizer |
