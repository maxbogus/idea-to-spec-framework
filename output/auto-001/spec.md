## 9. Архитектура (роль Architect)

### Компоненты

| Компонент | Ответственность |
|---|---|
| Web / мобильный клиент | конструктор мема, превью |
| API-сервис | шаблоны, генерация, аккаунты |
| Медиа-хранилище | готовые изображения |
| Платёжный адаптер | подписка / разовые платежи **[гипотеза]** |
| Модерация | проверка пользовательского контента |

### ADR

| ID | Решение | Контекст | Последствия |
|---|---|---|---|
| ADR-1 | Шаблоны мема хранить как параметризуемые данные, не как защищённые кадры | IP-риск | нужен юридический ревью; меньше риска |
| ADR-2 | Платежи через внешнего провайдера | нет своей инфраструктуры | зависимость от провайдера |
| ADR-3 | Модерация до публикации | UGC + IP | задержка публикации |

**Условие пересмотра ADR** (`methods/decision-keeper.md`): если юрист
подтвердит, что использование образов South Park недопустимо — ADR-1 и
продукт пересматриваются.

### Наблюдаемость

- метрики: созданные мемы, шаринг, конверсия в премиум;
- логи: ошибки генерации, отказы модерации;
- алерты: рост отказов модерации.

## 10. User flow (роль Designer)

1. Открытие → выбор шаблона.
2. Ввод текста трёх фаз (с подсказкой, что такое «Фаза 2»).
3. Превью → сохранить / поделиться.
4. Точки трения: пустой «Фаза 2» (сама суть мема) и страх нарушить IP.
