# Спецификация

> CRM для команд продаж 2–20 (B2B, РФ, SaaS-подписка за место). Режим прогона: `chat`
> (human-in-the-loop). Метки: **[факт]**, **[гипотеза]**, **[допущение]**, **[прогноз]**.

## 1. Назначение и scope

**Входит в MVP** **[факт]** (Q-12): воронка сделок; карточка клиента (контакты +
история переписки/звонков); задачи и напоминания; отчёты (воронка/конверсия/
выручка); автоматизация (триггеры + последовательности + напоминания);
интеграции почта/мессенджеры/IP-телефония/платежи; веб + PWA; биллинг подписки.

**НЕ входит в MVP** **[факт]** (выведено из Q-12, Q-8): нативные приложения
iOS/Android; маркетинговые кампании/рассылки; собственный VoIP; BI-платформа;
мультивалютность и мультиязычность; интеграции вне РФ.

## 6. Данные и безопасность

- ПДн: контакты (ФИО, email, телефон), переписка, записи звонков — **[факт]** (Q-14).
- 152-ФЗ: согласие, локализация БД и объектного хранилища в РФ, срок хранения
  (Q-17), минимизация, экспорт/удаление.
- Шифрование at rest и in transit; RBAC; аудит доступов.

**Сущности (источник ER):** Tenant, User, Company, Contact, Pipeline, Stage,
Deal, Task, Message, Call, AutomationRule, Sequence, Subscription, Invoice, AuditLog.

## 9. Архитектура и процессы

**Слои / компоненты (C4):**

- Presentation — PWA/веб (адаптив, offline-кэш).
- Application — API Gateway + CRM API (контакты, сделки, задачи, отчёты).
- Integration — Messaging/Integration Service (почта, мессенджеры, телефония, платежи), очередь, воркеры.
- Automation — движок правил и последовательностей.
- Billing — подписка, счета, чеки.
- Auth — OAuth2, RBAC, мультитенантность.
- Infrastructure — Postgres (РФ), Redis (кэш/очередь), Object storage (РФ).

**Процессы (DFD уровень 1):**

1. Управление контактами и сделками
2. Обмен сообщениями (интеграции)
3. Автоматизация (правила/последовательности)
4. Отчётность
5. Биллинг и подписка

**Хранилища (DFD / ER):**

- D1 — CRM БД (Postgres, РФ)
- D2 — Object storage: записи звонков, вложения (РФ)
- D3 — Очередь/кэш (Redis)

## 10. ADR

| ID | Решение | Контекст | Последствия |
|---|---|---|---|
| ADR-1 | Мультитенантная Postgres с tenant_id + RLS | SaaS, команды 2–20 | изоляция данных; дешевле на старте |
| ADR-2 | REST/JSON API + OAuth2 | веб + PWA | простые интеграции; версионирование API |
| ADR-3 | Асинхронные интеграции через очередь (Redis) + воркеры | внешние каналы, rate limits | устойчивость, retries, backpressure |
| ADR-4 | Записи звонков и вложения — в object storage, не в БД | объём данных | дешевле; нужен контроль доступа |
| ADR-5 | PWA вместо нативного мобайла в MVP | 6 мес / 5–15 млн ₽ | быстрее и дешевле; ограничения push на iOS |
| ADR-6 | БД и object storage — в РФ | 152-ФЗ | соответствие закону; уже выбор провайдеров |
